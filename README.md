# RenPy Studio

Настольная визуальная IDE для создания визуальных новелл на **Ren'Py** без кода.
Новелла собирается из блоков, `.rpy` генерируется автоматически — читаемый, комментированный,
идиоматичный код, который можно дальше править в VS Code.

> Неофициальный инструмент. Ren'Py — торговая марка Tom Rothamel / Ren'Py Project.

### Возможности редактора

- **Сцена** — вертикальная лента карточек, drag&drop, палитра из 21 типа блоков, инспектор свойств.
- **Точки и клики** — блок с фоном и кликабельными зонами: прямоугольники и многоугольники рисуются прямо на превью, у каждой зоны своя подпись и переход; генерируется готовый экран Ren'Py с маской клика по пикселям.
- **Граф** — узлы-сцены и (опционально) узлы-выборы/условия; block-level режим со всеми блоками, поиск по сценам, миникарта, подсветка тупиков и недостижимых сцен, перепривязка рёбер мышью.
- **Библиотека** — превью, поиск, drag&drop файлов из проводника и кнопка «Импортировать файлы…» (копии кладутся в `game/images|audio|fonts|video`, без перезаписи).
- **Персонажи** — имя, цвет, режим (обычный/мысли/рассказчик), тег спрайта, аватар, голос, префикс/суффикс.
- **Переменные** — число/флаг/текст, значения по умолчанию, конструктор условий из списков.
- **Экраны** — конструктор главного меню с живым предпросмотром.
- **GUI** — без кода правится всё, что обычно пишут в `gui.rpy`/`options.rpy`: разрешение, палитра, шрифты, фоны меню, высота текстового окна, сетка сохранений и опции проекта (название, переходы, звук/музыка/озвучка). Рядом — конструктор собственных экранов: текст/кнопка/картинка на холсте, действия (переход, меню, возврат, показать экран), пресеты «Меню», «Об игре», «HUD».

Тема генерируется в `game/zz_theme.rpy` с `init offset = -1`: он выполняется после шаблонного `gui.rpy`, но до сборки стилей, поэтому авторские файлы не перезаписываются.
- **История** — автоснимки перед запуском/сборкой, ручные снимки с названиями, структурный diff, откат в один клик (текущее состояние тоже сохраняется в историю).
- **Экспорт** — `game/*.rpy` с якорями блоков, `srcmap` для перехода из ошибок lint к блоку.
- **Локализация** — тексты по языкам в проекте + генерация `game/tl/<lang>` через SDK.
- **Сборка** — потоковый журнал из SDK, определение готового артефакта, защита от конфликтов с внешними правками.
- **Внешние изменения** — наблюдатель файлов, баннер и построчный diff «что именно изменилось», перечитывание после `git pull`.
- **Импорт** — разбор `.rpy`: знакомое превращается в блоки, остальное сохраняется в блоках «Код» и в `zz_init.rpy`; оригинальные имена меток сохраняются, поэтому существующие `jump`/`call` и переводы продолжают работать. Оригиналы складываются в `renpy-studio/imported-source/`.

## Быстрый старт (разработка)

Требования:

- Windows 10/11 x64
- **Node.js 20+**
- **Rust** (stable, MSVC)
- **Visual Studio Build Tools** с workload «Desktop development with C++» (MSVC + Windows SDK)
- **Ren'Py SDK** 8.x (в этом репозитории он лежит рядом: `..\renpy.exe`)

```powershell
cd studio
npm install
npm run tauri:dev        # запуск приложения (сам подхватит MSVC-окружение)
npm run tauri:build      # установщик NSIS в src-tauri\target\release\bundle\nsis
```

`npm run tauri:dev` и `npm run tauri:build` вызывают `scripts\tauri.ps1`, который импортирует окружение Visual Studio
и добавляет пути MSVC/Windows SDK — на этой машине VS стоит на нестандартном диске и без этого `link.exe` не находится.
Для ручных команд используйте `scripts\cargo.ps1 check` / `scripts\cargo.ps1 build --features cli`.

Артефакты релиза: `src-tauri\target\release\bundle\nsis\`.

Формат проекта — `renpy-studio/project.json` (источник истины) + `game/` (генерируемый артефакт).

## Генерируемый код

```renpy
# ═══════════════════════════════════════════════
# СЦЕНА: Пролог
# Файл сгенерирован RenPy Studio 0.1.0.
# Узел: 01932f4a-...
#
# Правьте смело, но помните: следующий экспорт из
# студии перезапишет этот файл. Блоки меняются в
# RenPy Studio, а этот код — читаемая точка входа.
# ═══════════════════════════════════════════════
label scene_prologue:

    # [блок 01932f4b · Смена фона]
    scene bg room with dissolve

    # [блок 01932f4c · Реплика]
    mira "Это начало…"

    # [блок 01932f4d · Выбор]
    menu:
        "Открыть дверь?":

        "Открыть дверь":
            $ trust += 1
            jump scene_door

        "Уйти" if trust > 0:
            jump scene_street
```

Правила: один файл на сцену, 4 пробела, `default` для переменных, человекочитаемые условия,
якоря `# [блок …]`, `renpy-studio/generated.json` хранит хеши и карту строк → блоков.

## SDK Ren'Py

Студия ищет SDK: настройки → переменная `RENPY_SDK` → родительская папка проекта → типовые места
(`%LOCALAPPDATA%`, `Downloads`, корни дисков с именем `renpy*`). Путь можно указать вручную.

Используется только CLI установленного SDK:

- запуск — `renpy.exe <project> run`
- lint — `renpy.exe <project> lint <report> --error-code` (отчёт парсится и привязывается к блокам)
- сборка — `renpy.exe launcher distribute <project> --package pc`

## MCP для ИИ-агентов

Настройки → «MCP-сервер» → включить (по умолчанию порт `8791`). Если сервер был включён, студия поднимает его при следующем запуске автоматически.

```json
{
  "mcpServers": {
    "renpy-studio": {
      "type": "http",
      "url": "http://127.0.0.1:8791/mcp"
    }
  }
}
```

Инструменты: `get_project_overview`, `get_scene`, `create_scene`, `update_scene`,
`create_say_block`, `create_menu_block`, `add_block`, `delete_block`, `list_characters`,
`upsert_character`, `list_variables`, `upsert_variable`, `search_text`,
`request_snapshot`, `list_snapshots`, `rollback`, `validate_project`.

Правила: сервер слушает только `127.0.0.1`; каждая мутация проходит валидатор (невалидный проект
отклоняется и откатывается), перед изменением создаётся снимок, блоки помечаются `source: "mcp"`,
UI показывает бейдж «Изменено через MCP».

## ИИ-ассистент

Настройки → «ИИ-ассистент»: URL провайдера (OpenAI-совместимый, обычно `https://…/v1`), ключ и модель.
Кнопка со значком ✦ в верхней панели открывает чат справа.

- Список моделей подтягивается из `GET /v1/models` (кнопка обновления в шапке панели).
- Ассистент видит структуру открытого проекта: сцены, персонажей, переменные и блоки текущей сцены.
- Если модель предлагает правки, в конце ответа появляется блок `actions`; панель показывает их списком
  и применяет только после кнопки «Применить» (`add_scene`, `add_block`, `set_start_scene`).
- Ключ отправляется только из Rust-стороны в заголовке `Authorization`, не логируется и не попадает в код проекта.

## Headless-режим (CI)

```powershell
renpy-studio.exe --new  C:\novels\demo "Моя новелла" --sdk "C:\renpy-8.5.3-sdk"
renpy-studio.exe --import C:\games\the_question --title "The Question"
renpy-studio.exe --export C:\novels\demo --force
renpy-studio.exe --lint   C:\novels\demo
```

Сквозная проверка генератора: `scripts\e2e.ps1` создаёт проект, подставляет фикстуру, экспортирует и прогоняет официальный `renpy lint`.

Другие проверки:

```powershell
npm run check                       # TypeScript + полнота RU/EN словарей
powershell -File scripts\cargo.ps1 test   # юнит-тесты генератора и истории
powershell -File scripts\e2e.ps1         # создание → экспорт → lint
```

CLI пишет в консоль, поэтому его удобно запускать из debug-сборки или из сборки с `--features cli`:
в обычном release-бинарнике подсистема Windows GUI и консольного вывода нет.

## Ограничения v1 и что осталось

- Обратный разбор `.rpy` выполняется только при импорте, постоянной синхронизации нет.
- При импорте несколько строк переводов (`tl/*.rpy`) могут стать «orphan», если текст в блоке был нормализован; сами переводы не удаляются.
- Полной виртуализации нет: у графа включён `onlyRenderVisibleElements` и линейная раскладка блоков,
  у карточек — `content-visibility`; очень большие сцены (тысячи блоков) всё равно будут тяжёлыми.
- Сборка проверена для Windows-пакета; mac/linux зависят от установленных пакетов SDK, готовый артефакт
  ищется в папке `dist`.
- Установщик не подписан (SmartScreen может предупредить). Подпись: `scripts\sign.ps1` — нужен сертификат OV/EV.
- Конструктор экранов покрывает главное меню; настройки/загрузка/About остаются стандартными Ren'Py.
- Плагины устанавливаются «как есть»: архив обычно содержит демо-игру, поэтому `gui.rpy`, `screens.rpy`,
  `options.rpy`, `script.rpy` и `tl/` пропускаются, а уже существующие файлы проекта не перезаписываются.
  Старые плагины могут не собираться на Ren'Py 8.5 (например, `SMS.rpy` использует несовместимое
  сочетание `xalign` + `xanchor`) — это ограничение самого плагина, а не студии.
- ИИ-ассистент работает через OpenAI-совместимый API; стриминга нет — ответ приходит целиком.

## Плагины

Папка `plugins/` рядом со студией — каталог плагинов Ren'Py (`.rpy`, папки, zip-архивы).
Вкладка **Плагины** показывает найденные наборы, описание, размер и файлы; включение копирует
game-файлы в проект (структура `game/` сохраняется, одиночные `.rpy` — в `game/plugins/<id>/`),
отключение удаляет только скопированное студией. Для плагинов с известным синтаксисом есть кнопка
«Вставить пример» (например, `Bub`, `with strat`). Инструкции (README/шапка `.rpy`) открываются
в модальном окне.

## Папки спрайтов персонажа

У персонажа есть поле «Папка спрайтов» (относительно `game/images`, подпапки разрешены).
Кнопка «Создать/открыть» делает папку и открывает проводник. В блоках «Показать спрайт» и
«Смена позы» появляется выбор позы из этой папки: путь превращается в атрибут (`happy/smile.png`
→ `happy smile`), а файл — в `asset`.
