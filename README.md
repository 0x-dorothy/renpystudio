# RenPy Studio

Настольная визуальная IDE для создания визуальных новелл на **Ren'Py** без кода.
Новелла собирается из блоков, `.rpy` генерируется автоматически — читаемый, комментированный,
идиоматичный код, который можно дальше править в VS Code.

> Неофициальный инструмент. Ren'Py — торговая марка Tom Rothamel / Ren'Py Project.

## Что уже работает

| Фаза ТЗ | Состояние |

| 3 — Библиотека ассетов, звук/музыка блоками, блок «Код», история версий (снимки, diff, откат), lint с переходом к блоку | готово (кроме drag&drop файлов из проводника) |
| 4 — Конструктор главного меню: шаблоны, фон/лого/музыка, предпросмотр, генерация `screen` | готово (главное меню) |
| 5 — Импорт `.rpy`, наблюдатель файлов, сборка релизов | импорт, наблюдатель и сборка через SDK готовы; официальный пример `the_question` импортируется и запускается |
| 6 — MCP-сервер для внешних ИИ-агентов | готово: Streamable HTTP, 17 инструментов, снимки и валидация |
| 7 — ИИ-ассистент | заготовка настроек (URL/ключ/модель), функции — v2 |

### Возможности редактора

- **Сцена** — вертикальная лента карточек, drag&drop, палитра из 20 типов блоков, инспектор свойств.
- **Граф** — узлы-сцены и (опционально) узлы-выборы/условия, рёбра трёх типов, миникарта, подсветка тупиков и недостижимых сцен.
- **Персонажи** — имя, цвет, режим (обычный/мысли/рассказчик), тег спрайта, аватар, голос, префикс/суффикс.
- **Переменные** — число/флаг/текст, значения по умолчанию, конструктор условий из списков.
- **Экраны** — визуальный конструктор главного меню с живым предпросмотром.
- **История** — автоснимки перед запуском/сборкой, ручные снимки, структурный diff, откат в один клик.
- **Экспорт** — `game/*.rpy` с якорями блоков, `srcmap` для перехода из ошибок lint к блоку.
- **Внешние изменения** — наблюдатель файлов, баннер «проект менялся вне студии», перечитывание после `git pull`.
- **Импорт** — разбор `.rpy`: знакомое превращается в блоки, остальное сохраняется в блоках «Код» и в `zz_init.rpy`; оригинальные имена меток сохраняются, поэтому существующие `jump`/`call` и переводы продолжают работать. Оригиналы складываются в `renpy-studio/imported-source/`.

## Быстрый старт (разработка)

Требования:

- Windows 10/11 x64
- **Node.js 20+**
- **Rust** (stable, MSVC)
- **Visual Studio Build Tools** с workload «Desktop development with C++» (MSVC + Windows SDK)
- **Ren'Py SDK** 8.x (в этом репозитории он лежит рядом: `..\renpy.exe`)

```powershell
cd studio
npm install
npm run tauri:dev        # запуск приложения (сам подхватит MSVC-окружение)
npm run tauri:build      # установщик NSIS в src-tauri\target\release\bundle\nsis
```

`npm run tauri:dev` и `npm run tauri:build` вызывают `scripts\tauri.ps1`, который импортирует окружение Visual Studio
и добавляет пути MSVC/Windows SDK — на этой машине VS стоит на нестандартном диске и без этого `link.exe` не находится.
Для ручных команд используйте `scripts\cargo.ps1 check` / `scripts\cargo.ps1 build --features cli`.

Артефакты релиза: `src-tauri\target\release\bundle\nsis\`.

## Структура

```
studio/
├── src/                     # React + TypeScript (UI)
│   ├── components/          # окно, панели, редактор сцены, граф, модальные окна
│   ├── blocks/registry.ts   # схемы всех блоков (поля, иконки, категории)
│   ├── store.ts             # Zustand: проект, выделение, настройки, события
│   ├── locales/             # RU/EN словари
│   └── types.ts             # зеркало модели Rust
├── src-tauri/
│   └── src/
│       ├── model.rs         # модель проекта (serde), slugify, локализованный текст
│       ├── store.rs         # чтение/запись project.json, undo/redo, снимки
│       ├── generator.rs     # генератор .rpy (якоря, srcmap, комментарии)
│       ├── exporter.rs      # запись в game/, манифест, защита от внешних правок
│       ├── validation.rs    # проверки ссылок, тупиков, недостижимых сцен + граф
│       ├── importer.rs      # разбор .rpy → блоки (best effort)
│       ├── sdk.rs           # поиск SDK, запуск, lint, сборка
│       ├── mcp.rs           # MCP-сервер (Streamable HTTP, JSON-RPC)
│       ├── watcher.rs       # наблюдение за папкой проекта
│       ├── commands.rs      # IPC-команды Tauri
│       └── cli.rs           # headless: --new / --export / --lint
├── scripts/
│   ├── cargo.ps1            # cargo с окружением MSVC
│   ├── msvc-env.ps1         # поиск Visual Studio / Windows SDK
│   ├── tauri.ps1            # tauri dev/build с окружением MSVC
│   ├── e2e.ps1              # создать проект → экспорт → Ren'Py lint
│   ├── make_icon.py         # иконки приложения
│   ├── make-fixture-assets.py # ассеты для e2e-фикстуры
│   ├── check-i18n.mjs       # проверка полноты словарей
│   └── cdp.mjs              # отладка UI через WebView2 DevTools (dev)
└── tests/fixture/           # проект-фикстура для e2e
```

Формат проекта — `renpy-studio/project.json` (источник истины) + `game/` (генерируемый артефакт).
Ассеты лежат в стандартных папках Ren'Py и не дублируются.

## Генерируемый код

```renpy
# ═══════════════════════════════════════════════
# СЦЕНА: Пролог
# Файл сгенерирован RenPy Studio 0.1.0.
# Узел: 01932f4a-...
#
# Правьте смело, но помните: следующий экспорт из
# студии перезапишет этот файл. Блоки меняются в
# RenPy Studio, а этот код — читаемая точка входа.
# ═══════════════════════════════════════════════
label scene_prologue:

    # [блок 01932f4b · Смена фона]
    scene bg room with dissolve

    # [блок 01932f4c · Реплика]
    mira "Это начало…"

    # [блок 01932f4d · Выбор]
    menu:
        "Открыть дверь?":

        "Открыть дверь":
            $ trust += 1
            jump scene_door

        "Уйти" if trust > 0:
            jump scene_street
```

Правила: один файл на сцену, 4 пробела, `default` для переменных, человекочитаемые условия,
якоря `# [блок …]`, `renpy-studio/generated.json` хранит хеши и карту строк → блоков.

## SDK Ren'Py

Студия ищет SDK: настройки → переменная `RENPY_SDK` → родительская папка проекта → типовые места
(`%LOCALAPPDATA%`, `Downloads`, корни дисков с именем `renpy*`). Путь можно указать вручную.

Используется только CLI установленного SDK:

- запуск — `renpy.exe <project> run`
- lint — `renpy.exe <project> lint <report> --error-code` (отчёт парсится и привязывается к блокам)
- сборка — `renpy.exe launcher distribute <project> --package pc`

## MCP для ИИ-агентов

Настройки → «MCP-сервер» → включить (по умолчанию порт `8791`). Если сервер был включён, студия поднимает его при следующем запуске автоматически.

```json
{
  "mcpServers": {
    "renpy-studio": {
      "type": "http",
      "url": "http://127.0.0.1:8791/mcp"
    }
  }
}
```

Инструменты: `get_project_overview`, `get_scene`, `create_scene`, `update_scene`,
`create_say_block`, `create_menu_block`, `add_block`, `delete_block`, `list_characters`,
`upsert_character`, `list_variables`, `upsert_variable`, `search_text`,
`request_snapshot`, `list_snapshots`, `rollback`, `validate_project`.

Правила: сервер слушает только `127.0.0.1`; каждая мутация проходит валидатор (невалидный проект
отклоняется и откатывается), перед изменением создаётся снимок, блоки помечаются `source: "mcp"`,
UI показывает бейдж «Изменено через MCP».

## Headless-режим (CI)

```powershell
renpy-studio.exe --new  C:\novels\demo "Моя новелла" --sdk "C:\renpy-8.5.3-sdk"
renpy-studio.exe --import C:\games\the_question --title "The Question"
renpy-studio.exe --export C:\novels\demo --force
renpy-studio.exe --lint   C:\novels\demo
```

Сквозная проверка генератора: `scripts\e2e.ps1` создаёт проект, подставляет фикстуру, экспортирует и прогоняет официальный `renpy lint`.

Другие проверки:

```powershell
npm run check                       # TypeScript + полнота RU/EN словарей
powershell -File scripts\cargo.ps1 test   # юнит-тесты генератора и истории
powershell -File scripts\e2e.ps1         # создание → экспорт → lint
```

CLI пишет в консоль, поэтому его удобно запускать из debug-сборки или из сборки с `--features cli`:
в обычном release-бинарнике подсистема Windows GUI и консольного вывода нет.

## Ограничения v1 и что осталось

- Обратный разбор `.rpy` выполняется только при импорте, постоянной синхронизации нет.
- При импорте несколько строк переводов (`tl/*.rpy`) могут стать «orphan», если текст в блоке был нормализован; сами переводы не удаляются.
- Нет drag&drop файлов из проводника в библиотеку (файлы кладутся в `game/images` / `game/audio` вручную; библиотека их подхватывает).
- Лента сцен не виртуализирована: очень большие проекты (тысячи блоков в одной сцене) будут подтормаживать.
- Экспорт переводов в `tl/<lang>` не автоматизирован: текст хранится по локалям, а файлы переводов создаются командой SDK `renpy translate`.
- Сборка релизов проверена для Windows-пакета; mac/linux зависят от установленных пакетов SDK.
- Установщик не подписан (SmartScreen может предупредить).
- ИИ-ассистент — только настройки провайдера (v2 по ТЗ).
